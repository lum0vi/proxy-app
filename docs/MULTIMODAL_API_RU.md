# API моделей, изображений и видео

Один клиентский ключ и баланс работают с несколькими каналами поставщиков. Публичный контракт — `apps/web/public/openapi.yaml`; инструкции покупателю — `/setup` и `/docs#media`. Покупатель видит наш адрес API, свой ключ, модель и тариф.

## Маршруты

| Назначение | Маршрут | Авторизация |
|---|---|---|
| GPT, Grok: Responses | `POST /v1/responses` | `Authorization: Bearer ...` |
| GPT, Grok, DeepSeek и совместимые модели | `POST /v1/chat/completions` | Bearer |
| Stateless compaction | `POST /v1/responses/compact` | Bearer |
| Claude | `POST /v1/messages` | `x-api-key` или Bearer |
| Подсчёт токенов Claude | `POST /v1/messages/count_tokens` | `x-api-key` или Bearer |
| Gemini | `POST /v1beta/models/{model}:generateContent` | `x-goog-api-key` или Bearer |
| Gemini SSE | `POST /v1beta/models/{model}:streamGenerateContent?alt=sse` | `x-goog-api-key` или Bearer |
| Подсчёт токенов Gemini | `POST /v1beta/models/{model}:countTokens` | `x-goog-api-key` или Bearer |
| Каталог / одна модель | `GET /v1/models`, `GET /v1/models/{model}` | Bearer; с Anthropic-заголовками — формат Anthropic |
| Каталог Gemini / одна модель | `GET /v1beta/models`, `GET /v1beta/models/{model}` | `x-goog-api-key` или Bearer |
| Генерация изображений | `POST /v1/images/generations` | Bearer |
| Редактирование изображений | `POST /v1/images/edits` | Bearer |
| Создание / список видео | `POST /v1/videos`, `GET /v1/videos` | Bearer |
| Статус / скачивание видео | `GET /v1/videos/{id}`, `GET /v1/videos/{id}/content` | Bearer |

У Gemini также принимается путь `/v1/models/{model}:...`, который направляется в настроенный канал `/v1beta`. Секреты передавайте в заголовках, не в URL. Для Google GenAI SDK задавайте `httpOptions: { baseUrl: "https://ваш-домен", apiVersion: "v1beta" }`.

Текстовые запросы сохраняют native JSON, tool calls, multimodal input и SSE соответствующего протокола. Считаются подтверждённые usage, кэш и thinking tokens. Подсчёт токенов не списывает баланс, но требует доступного ключа и занимает слот конкурентности. Если поставщик не поддерживает этот метод, прокси возвращает ошибку, а не выдуманное число.

Это совместимость перечисленных маршрутов, а не автоматическая конвертация любого протокола в любой другой. Доступные сочетания модели и протокола видны в каталоге. Хранимые у общего аккаунта conversations, file IDs, provider-hosted tools, realtime, batch и web search не включены: для них нужны отдельные изоляция и тарифы.

## Подключение каналов в админке

1. **Провайдеры → Добавить провайдера**: укажите корневой Base URL без `/v1`, протокол и основной пул в поле «Объединить с пулом». Для Claude — `ANTHROPIC`, Gemini — `GEMINI`, Chat Completions — `OPENAI_CHAT`, Responses + Chat — `OPENAI`, изображений — `IMAGES`, видео — `VIDEOS`.
2. Добавьте ключ поставщика и допустимое количество одновременных запросов. Проверка каталога должна пройти успешно; для видео требуется каталог `GET /v1/models` у совместимого поставщика.
3. Задайте **закупочные** ставки. Наценка применяется один раз; при `PRICE_MARKUP=2` и `BILLING_USDT_PER_USD=1` ставка покупателя вдвое выше закупочной. Для видео укажите цену за секунду, остальные ставки — нули.
4. Укажите параметры, включённые в эту цену. Например, видео: `{"seconds":[4,8],"size":["1280x720"]}`. Изображения с разрешённым редактированием: `{"operations":["edit"],"size":["1024x1024"],"quality":["medium"]}`. Это примеры конфигурации, не утверждение о тарифах конкретного поставщика.
5. Если параметр разрешён в `mediaOptions`, клиент обязан явно выбрать одно из его значений. Запрошенный, но не настроенный `size`, `quality`, `audio`, `resolution` и другие тарифицируемые параметры отклоняются до обращения к поставщику. Все разрешённые варианты должны иметь одну указанную закупочную ставку.

Не включайте дорогие варианты в дешёвый тариф. Если цены отличаются, нужны отдельные доступные upstream model IDs/тарифы; автоматического перерасчёта стоимости по размеру или качеству здесь нет. Операция редактирования должна быть явно разрешена после проверки её закупочной цены. Положительная ставка сама по себе не подтверждает возможности поставщика.

Новые медиа-модели и вымышленные закупочные цены не добавляются в каталог автоматически. Нужны их реальные API-ключи, ID моделей, доступность маршрутов и цены. Текущий адаптер видео использует совместимый `/v1/videos` API; он не преобразует напрямую Google long-running operations или собственный xAI video API. Для таких поставщиков нужен совместимый шлюз или отдельный адаптер.

## Изображения

JSON generation; JSON с HTTPS/data-URI изображениями или multipart upload для edits. Разрешены PNG, JPEG и WebP, до 16 входных файлов, общий запрос до 32 MiB. Для нескольких файлов — повторяющиеся поля `image[]`; `mask` — один файл. Передача чужих upstream `file_id` запрещена. Генерация и редактирование возвращают обычный JSON, streaming images не включён.

Резерв определяется параметром `n`, списание — количеством реально возвращённых изображений (не больше `n`). Ошибка HTTP не списывает баланс. Неопределённый результат учитывается как инцидент сверки; выдуманные токены не начисляются.

## Видео и деньги

При создании сервер атомарно сохраняет собственный ID `video_<uuid>`, снимок тарифа, связь с клиентским ключом и резерв. Промпты и загруженные файлы в таблицу задач не сохраняются. Полный upstream ключ в снимок не попадает.

- Укажите `Idempotency-Key` и сохраняйте его вместе с параметрами запроса. Повтор с теми же данными вернёт ту же задачу, даже после перезапуска; другие данные с тем же ключом дают `409`.
- Пока задача `queued`/`in_progress`, резерв удерживается и занимает слот конкурентности. Его видно в карточке клиентского ключа. Резерв не исчезает из-за рестарта или обычной очистки краткосрочных leases.
- Worker проверяет незавершённые задачи; `GET` статуса также обновляет их с ограничением частоты. Подтверждённый `completed` списывает цену за подтверждённую длительность ровно один раз. `failed` освобождает резерв.
- Timeout, 5xx при создании, потерянный ID, слишком долгое ожидание (`VIDEO_JOB_TIMEOUT_MS`, по умолчанию сутки) не считаются доказательством бесплатного отказа. Задача переходит в `billing_status: review_required`; автоматического повторного создания нет.
- **Админка → Провайдеры → Задачи генерации видео**: сверить результат по upstream ID или освободить резерв без списания с обязательным основанием. При сверке проверяются модель и длительность; одно upstream видео нельзя привязать двум задачам. Решение и расчёт записываются одной транзакцией вместе с audit log.
- После потери соединения нельзя генерировать новый Idempotency-Key «для повтора»: поставщик мог принять первую задачу. При неизвестном результате оператор должен сначала свериться с поставщиком.
- Каталог задач и скачивание изолированы по клиентскому ключу. Исчерпанный ключ может забрать уже оплаченный результат. Отозванный ключ и заблокированный пользователь — нет. Ротация секрета того же ключа сохраняет доступ.
- Статус и скачивание не списывают деньги. Контент проксируется потоком, до 512 MiB; redirects поставщика не раскрываются и не выполняются. Файлы не архивируются навсегда: срок хранения зависит от поставщика.

Метрики: `proxiapp_video_jobs{state=...}`, `proxiapp_video_poll_lag_seconds`; Prometheus alerts: `VideoJobsNeedReview`, `VideoPollingStale`. В Grafana добавлены задачи по состояниям и задержка проверки.

## Пакеты и рубли

Стандартные пакеты при наценке ×2: **1, 2, 5, 20, 50 USDT**. Они подходят для нового ключа и пополнения действующего. У всех одинаковая цена токенов; количество одновременных запросов зависит от пакета. Изменение глобальной наценки меняет цену будущих покупок по прежним правилам приложения.

Рублёвый эквивалент загружается по курсу USDT/RUB из CoinGecko, отображается с временем обновления даже при оплате только в USDT. Можно задать `USDT_RUB_RATE` вручную. Курс не зашит в интерфейс. Для настоящей оплаты рублями настройте `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, добавьте `yookassa` в `PAYMENT_METHODS` и `RUB` в `PAYMENT_CURRENCIES`; сумма и курс сохраняются при создании счёта, баланс зачисляется в USDT.

## Проверка и границы доказательств

`npm test` при `RUN_INTEGRATION_TESTS=true` запускает реальные HTTP-вызовы официальных SDK OpenAI, Anthropic и Google к приложению и локальным Fastify-имитациям. Используется отдельный PostgreSQL, без реальных платежей, генерации или передачи клиентских данных поставщикам. Проверяются JSON/SSE, native usage, multipart edits, видео, идемпотентность, чужой ключ, исчерпанный баланс, конкурентное резервирование, сбой поставщика, админское решение и пополнения 1/2/5 USDT/RUB. Отдельный тест применяет миграции 014/015 поверх заполненной схемы 013.

Контракты сверены 25.11.2026: [Nodule API setup](https://nodule-provider.store/setup), [Anthropic API](https://platform.claude.com/docs/en/api/overview), [Gemini token counting](https://aistudio.google.com/api-reference/tokens/count-tokens), [xAI Chat Completions](https://docs.x.ai/developers/rest-api-reference/inference/chat-completions). Историческая схема OpenAI Videos использована только как форма совместимости; доступность конкретных видео-моделей определяется фактическим поставщиком.

Это подтверждает работу нашего кода с описанными контрактами, но не доступность реальных платных моделей. Перед включением каждого канала нужна проверка небольшого настоящего запроса и закупочного списания у выбранного поставщика. Postman CLI на этой машине завершился ошибкой macOS Keychain (`SecItemCopyMatching -50`); использованы повторяемые HTTP-интеграционные тесты в репозитории, удалённые коллекции/моки не публиковались.
